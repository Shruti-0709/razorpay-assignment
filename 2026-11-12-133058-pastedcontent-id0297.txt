❯ how is the storage working where are we storing the data

● The data is kept only in a JavaScript variable in the browser's memory.
  Nothing is saved anywhere: no backend, no database, no localStorage.

  Where: paymentLinksService.ts (src/services/paymentLinksService.ts)

  let store: PaymentLink[] = createSeedPaymentLinks(new Date());

  How it works:
  1. On page load, store is filled with the 4 demo links from
     mocks/paymentLinks.ts (src/mocks/paymentLinks.ts). Their dates are set
     relative to the current time, so there is always one Active, one Paid and
     one Expired example.
  2. getPaymentLinks() waits 350 ms to mimic a network call, then returns a copy
     of store, newest first.
  3. createPaymentLink(input) waits 350 ms, builds the link (ID plink_…,
     createdAt = now, paidAt = null), adds it to the front of store and returns
     it.
  4. The usePaymentLinks hook (hooks/usePaymentLinks.ts
     (src/hooks/usePaymentLinks.ts)) calls these functions and holds the list in
     React state for the UI. After a create, it adds the new link to that list.

  What that means:
  - A page reload (or closing the tab) loses every link you created and brings
    back the 4 demo links.
  - Each browser tab has its own separate copy.
  - Status is never saved. It's worked out from paidAt and expiresAt each time
    the list is shown.

  Why it's built this way: the brief allows in-memory or mocked data. The UI
  only calls getPaymentLinks and createPaymentLink, so a real API can replace
  the inside of those two functions later without changing any component.

  To keep links across reloads, store could be saved to localStorage — about 5
  lines in the service.
